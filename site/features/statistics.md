# 统计分析

每次访问**异步**记账，不阻塞跳转响应。你看到的是多维聚合 + 可下钻的访客明细。

## 数据怎么流

```text
访问事件
   ↓  同步解析 UA / IP，异步入队
热层 · Redis
   PV/UV 原子计数、小时分布、设备/地域 Hash、访问日志队列
   ↓  Worker 约每 5 秒批量写库
温层 · MySQL access_logs
   原始明细，默认保留约 90 天
   ↓  定时任务把「非今日」计数落盘
冷层 · MySQL stat_*
   stat_daily / stat_hourly / stat_device / stat_geo
   ↓
管理端查询（优先读冷层；今日读明细，保证和访客列表一致）
```

90 天前的明细会搬到归档表，查询仍可联合归档。

## 你能看什么

### 单链接统计

- 顶部卡片：总 PV、总 UV、今日 PV、今日 UV、昨日 PV  
- 趋势：近 7/30 天或自定义区间（最长约 90 天）PV/UV 折线  
- 小时：当日或所选范围内 24 小时分布  
- 设备：mobile / tablet / desktop / bot / unknown  
- 系统 / 浏览器：iOS、Android、Chrome、微信内、QQ 内等  
- 地域：国家 / 省份，支持世界与中国地图概览 + TOP 排行  

### 全部链接 / 全局

- 统计页链接选择器可选「全部链接」  
- 全站汇总走专用聚合接口，不靠遍历所有链接发一堆请求  
- 概览看板：今日 PV、活跃链接、新增链接、TOP 链接、近 7 天趋势

### 访客明细

- 联合保留期 + 归档表  
- 支持链接、关键词、时间范围（开始含、结束不含）  
- 快捷范围：今天、最近 24 小时、近 7 天、近 30 天  
- 稳定分页：按访问时间 + 记录号倒序  
- 字段：时间、IP 解析地域、UA 设备、Referer、是否经中转等

今日明细依赖异步消费，通常数秒后可见；历史聚合按定时任务落盘。更多说明见[访客记录](./visitors)。

## 精度说明

| 指标 | 精度 | 说明 |
|------|------|------|
| PV | 精确 | 原子自增 |
| UV | 约 99% | HyperLogLog，误差 &lt; 1% |
| 地域 | 省级（国家可分） | 镜像内置 ip2region，离线解析 |
| UA | 设备/系统/浏览器 | 识别不了标 unknown，不造假 |
| 累计 UV | **不是**逐日 UV 简单相加 | 界面会标明口径，避免误读 |

未启用 IP 库时地域为空，不影响 PV/UV。

## 时间范围规则

- 完整时间戳按服务器本地时区解释  
- 范围左闭右开  
- 跨度超过 90 天或非法区间会返回明确错误  
- 「最近 24 小时」是滚动窗口；「今日」是自然日  

## 运营上怎么用

1. 投放前：给每条渠道码单独建统计入口  
2. 投放中：看小时分布判断峰值；看设备判断是否应优化移动页  
3. 投放后：按渠道对比 PV/UV；导出或截图复盘  
4. 排查：访客明细看 Referer 和 UA，判断是不是被爬或被误点
