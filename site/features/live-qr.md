# 群活码

对外只发布**一个固定短链**，后台按策略分发不同目标（常见是微信群二维码）。群满自动切下一个，印刷物料不用换。

## 核心概念

| 概念 | 说明 |
|------|------|
| 群活码链接 | 固定短码（`type=liveqr`），发布后对外不变 |
| 路由策略 | 如何在多个目标里选一个（轮询 / 权重） |
| 路由目标 | 每个目标的二维码 URL 或跳转 URL，可配名称、权重、扫码上限、到期时间、群主 |
| 落地页 | 必须关联 `liveqr` 模板页，渲染时注入当前选中的目标 |

## 已上线策略

### round_robin（轮询 + 上限）

按目标列表**顺序**使用未耗尽的目标；每个目标有扫码上限，到了就切下一个。

```text
目标：群1(上限200) → 群2(上限200) → 群3(上限200)

访问 1–200   → 群1
访问 201–400 → 群2
访问 401–600 → 群3
之后全部耗尽 → 落地页显示「暂无可用群」
```

说明：

- 行为是「优先用第一个未达上限的目标」，不是严格意义上的每次循环一圈  
- 上限留空表示不限次  
- 换了新群二维码后，可在后台**重置该目标计数**重新启用  

### weighted（加权随机）

按权重比例随机选目标，适合想把流量摊开的场景。

```text
群1 weight=3，群2 weight=1，群3 weight=1
→ 约 60% / 20% / 20%
```

已耗尽的目标会被过滤后，在剩余目标上重新按权重分配。

::: info 规划中、当前不可选
`time_based`（按时间段）、`geo_device`（按地域/设备）在工程规划里，管理端**不会**作为选项出现。
:::

## 创建步骤

1. **链接** → 新建，类型选**群活码**  
2. 选择**分发策略**：轮询或权重  
3. 填**二维码目标**（至少一行）：  
   - 名称（如「群1」）  
   - 图片/跳转 URL（`http(s)://`）  
   - 轮询：扫码上限；权重：权重值  
4. 选择 `liveqr` **落地页**及其落地域名  
5. 选择入口域名，保存

### 目标来源建议

- 从系统**素材库**选择已上传的群二维码 → 存为同源 `/uploads/...`，公开页随当前访问域名加载  
- 不要写死 `localhost` / `127.0.0.1`，手机打不开  
- 外部 `http(s)` 图片地址可以原样保留  

## 计数与耗尽

- 实时扫码计数以服务端原子更新为准；超过上限该目标标记耗尽并跳过  
- 管理端每个目标显示 `已扫/上限`（如 `156/200`）  
- 编辑目标时不会清掉历史累计；只有你显式点「重置计数」才从 0 再来  
- 目标到期后不再参与选择；**全部**不可用时展示统一的不可用页  

## 落地页如何展示

1. 用户打开入口短链  
2. 路由引擎选出一个目标  
3. 落地页模板拿到该目标 URL：  
   - 是图片 → 展示二维码 + 提示文案  
   - 是链接 → 展示按钮或引导跳转  
4. 页面响应 `Cache-Control: no-store`，避免浏览器缓存旧群码  

直访落地域时也会校验：链接停用 404、过期 410，且**拒绝时不增加扫码计数**。

## 运营清单

- 线下海报只印入口短链/二维码，永不变  
- 群快满时：后台新增目标（新群码）→ 调整顺序或权重 → 旧目标可停用  
- 换了同一群的码图：更新该目标 URL，或上传新图后重置计数  
- 定期看计数，避免全部耗尽导致落地页无码
