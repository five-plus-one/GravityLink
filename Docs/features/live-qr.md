# 功能规格：群活码

## 功能描述

群活码通过一个固定短链接，根据配置的轮换策略动态分发不同的目标（通常是微信群二维码）。解决微信群人满后需要换群码的问题，用户侧链接永不变。

## 核心概念

- **群活码链接**：一个固定短码（`type = 'liveqr'`），对外发布后不再变化
- **路由策略**：决定如何在多个目标中选择（`routing_strategies`）
- **路由目标**：每个目标对应一个二维码或跳转 URL（`routing_targets`）
- **落地页**：展示选中目标的二维码图片，用户扫码加群

## 轮换策略（4 种模式）

> 实现状态（2026-09）：当前 API 与路由引擎已落地 `round_robin`、`weighted`；`time_based`、`geo_device` 仍为规划能力，管理端不得展示为可选项。

### 1. round_robin（轮询 + 次数限制）

最基础的模式，按顺序轮换，每个目标设定扫码上限。

```
目标列表：[群1(上限200), 群2(上限200), 群3(上限200)]

扫码 1-200   → 群1
扫码 201-400 → 群2
扫码 401-600 → 群3
扫码 601+    → 所有目标已满，展示"暂无可用群"提示
```

实现：`routing:scan:{target_id}` 用 Redis INCR 计数，超过 `scan_limit` 则标记 `exhausted`，跳过选下一个。

### 2. weighted（带权重的随机）

多目标按权重比例随机分配，适合负载均衡场景。

```
目标列表：[群1(weight=3), 群2(weight=1), 群3(weight=1)]
群1 概率 60%，群2 和群3 各 20%
```

实现：Go 侧用 `math/rand` 加权随机选取（过滤掉 `exhausted` 目标后重算权重）。

### 3. time_based（按时间段）

不同时间段分配不同目标，适合有运营时段的场景。

```
目标配置：
  群1: time_start=09:00, time_end=18:00, weekday_mask=0b0111110 (周一到周五)
  群2: time_start=18:00, time_end=23:59, weekday_mask=0b1111111 (每天)
  群3: 无时间限制（兜底）

当前时间 10:00 周三 → 群1
当前时间 20:00 周三 → 群2
当前时间 03:00 周三 → 群3（兜底）
```

实现：服务器时间与目标的 `time_start/time_end/weekday_mask` 对比，按 `priority` 降序匹配第一个符合的目标。

### 4. geo_device（按地域/设备）

根据访客 IP 归属地或设备类型分配不同目标。

```json
// 目标 geo_filter 示例
{"provinces": ["广东", "广西"]}

// 目标 device_filter 示例
{"devices": ["mobile"]}  // 只匹配手机端
```

可与 round_robin 或 weighted 组合使用（`routing_strategies.mode` 支持混合）。

### 策略组合规则

多种维度可组合，执行顺序：
1. 过滤掉 `status != active` 的目标
2. 应用 `time_based` 过滤
3. 应用 `geo_device` 过滤
4. 在剩余目标中执行 `round_robin` 或 `weighted`
5. 若无可用目标，展示"暂无可用"落地页

## 扫码计数

- Redis INCR `routing:scan:{target_id}` 做实时计数（原子操作）
- 超过 `scan_limit` 时：Redis 返回结果 > scan_limit → 不再选此目标 → 更新 DB `status = exhausted`
- Worker 定时将 Redis 计数同步回 DB `routing_targets.scan_count`（非强一致，容忍秒级延迟）

## 落地页展示

群活码必须关联落地页（`template = 'liveqr'`）。落地页渲染时：

1. Page Handler 收到请求
2. 执行轮换策略，选出目标 `target_url`（即二维码图片 URL 或跳转 URL）
3. 将目标 URL 传入落地页模板渲染
4. 若 `target_url` 是图片，落地页展示二维码图片 + 扫码提示文案
5. 若 `target_url` 是跳转链接，落地页展示按钮或自动跳转

## 管理端功能

- 创建群活码：选择轮询或权重模式 → 用结构化目标行填写名称、URL、权重与扫码上限
- 目标状态可视化：每个目标显示当前扫码数 / 上限（如 `156/200`）
- 一键重置某目标计数（用于换群码后重新启用）
- 批量导入目标（粘贴多个群链接）

### Phase 7 管理端交互基线

- 创建弹窗先选择链接类型；活码类型展示独立的“分发策略”和“二维码目标”配置区。
- 从系统素材库选择的二维码保存为同源 `/uploads/...` 地址，公开落地页随当前访问域名加载图片，不能固化 `localhost` 或 `127.0.0.1`。历史 loopback 素材地址在渲染时兼容转换为同源地址；外部 HTTP(S) 图片保持原地址。
- `round_robin` 隐藏权重输入，按目标顺序轮换；`weighted` 展示权重输入。
- 目标至少保留一行，每行就地校验 HTTP/HTTPS URL；扫码上限留空表示不限。
- 目标详情、计数重置和批量导入依赖后续目标管理 API，本阶段不伪造前端功能。

### 2026-09-06 验收约束

路由目标在服务端复用短链 HTTP/HTTPS URL 校验，非法协议返回 400。round_robin 的当前行为遵循上方次数限制示例：优先使用首个未达上限目标，达到上限后切换；不声称每次访问循环。

# 2026-09-07 补齐实施约定

图片验收须确认浏览器 naturalWidth 非零且内容为二维码，不能以 HTML 中存在 img 标签或 URL 为通过。历史自动验收的 example.com/*.png 是占位地址，改为本机上传的、明确标注演示用途的二维码。正式用户目标不自动替换。加载失败时公开页显示失败说明，管理端显示图片预览以便发现错误 URL。

扫码计数以数据库原子条件更新为准，避免 Redis 重启后从零计数和并发超阈值；争用耗尽时尝试下一目标。编辑目标不得覆盖累计计数字段。

创建表单选择 liveqr 落地页并传递其域名，后端校验入口域和页面用途。目标管理保留原目标 ID 与累计访问数，支持修改图片 URL、标签、扫码阈值、权重、优先级、启停、到期时间和群主。新增 ExpireAt、Owner 字段，只做增量迁移。到期目标不参与选择；所有目标不可用显示既有不可用页面。管理入口单独加载目标，禁止编辑时用空白目标覆盖实际配置。
